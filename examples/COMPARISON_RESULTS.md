## 🎯 实测启示

### 发现 1：启动开销巨大

```
Rust 版本架构：
  输入 → 词法分析 (1ms) → 语法树 (2ms) → 渲染 (20ms) → PNG (766ms)
  总耗时：791ms，其中 97% 用在 PNG 转换（合理）

mmdc 架构：
  输入 → Node.js 启动 (100ms) → 加载库 (100ms) → 启动 Chromium (2000ms)
         → 页面渲染 (500ms) → 截图 (200ms) → 输出
  总耗时：2900ms，其中 69% 用在 Chromium 启动（浪费）
```

**结论**：mmdc 的性能瓶颈是浏览器依赖，与图表复杂度无关。

**Rust 版本**：

### 场景 2：Kubernetes 部署

**需求**：容器镜像 < 200MB，支持快速扩展


### 场景 3：CI/CD 流水线

**需求**：处理 1000 个图表，总耗时 < 5 分钟

```
mmdc:
  1000 图 × 2.9s/图 = 2900s = 48 分钟 ❌ 超时

Rust:
  1000 图 × 0.8s/图 = 800s = 13 分钟 ✅ 通过
  
改进：批处理 (50 并发)
  mmdc: 48分钟 ÷ 50 = ~1 分钟 (如果内存充足) ⚠️
  Rust: 13分钟 ÷ 50 = ~16 秒 ✅ 极快
```

**内存瓶颈**：
```
mmdc: 50 个进程 × 500MB = 25GB ❌ OOM
Rust: 50 个进程 × 30MB = 1.5GB ✅ 轻松
```

## 🎓 学习点

这次对比揭示了一个重要的原则：

> **"选择工具不仅看功能完整度，更要看部署成本和运行效率。"**

mmdc 功能更全面，但浏览器依赖的架构决定了它注定慢。  
这不是代码问题，而是架构问题——无法通过优化突破浏览器启动的瓶颈。

Rust 版本则通过直接 SVG 生成和轻量级 PNG 转换，达到了最优的性能-功能平衡。
