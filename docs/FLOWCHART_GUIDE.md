# 流程图完整指南

## 什么是流程图？

流程图（Flowchart）是用来展示**过程中的步骤和决策**的图表。

- **节点** = 过程中的各个步骤
- **箭头** = 步骤之间的流向
- **菱形** = 决策点（if/else 分支）
- **方形** = 过程/动作

---

## 📍 流程图的核心元素

### 1. 节点类型（Node Types）

| 图形 | 形状 | 代码 | 用途 |
|------|------|------|------|
| 🟢 | 圆形 | `Start([开始])` | 流程开始 |
| 📦 | 方形 | `A["步骤A"]` | 普通过程 |
| 🔷 | 菱形 | `B{条件?}` | 决策/判断 |
| 📌 | 圆形 | `End([结束])` | 流程结束 |
| ⚠️ | 方形 | `Error["❌ 错误"]` | 错误状态 |

### 2. 连接方式（Connections）

| 连接 | 代码 | 含义 |
|------|------|------|
| → | `A --> B` | 正常流向 |
| →\|标签\| | `A -->|是\| B` | 带条件的流向 |
| → | `A --> B` | 顺序执行 |

### 3. 流向方向（Flow Directions）

| 方向 | 代码 | 显示 |
|------|------|------|
| 从上到下 | `flowchart TD` | 竖向布局 ✅ 推荐 |
| 从下到上 | `flowchart BU` | 反向竖向 |
| 从左到右 | `flowchart LR` | 横向布局（宽） |
| 从右到左 | `flowchart RL` | 反向横向 |

**建议**：使用 `TD`（从上到下）可以获得最清晰的渲染效果。

## 🎯 实际案例：电商结账流程

### Mermaid 代码

```mermaid
flowchart TD
    Start([开始结账]) --> A["1️⃣ 验证购物车"]
    A --> B{"购物车<br/>有效?"}
    B -->|否| Err1["❌ 返回修改"]
    Err1 --> End([结束])

    B -->|是| C["2️⃣ 计算价格"]
    C --> D{"价格<br/>正确?"}
    D -->|否| Err2["❌ 重新计算"]
    Err2 --> End

    D -->|是| E["3️⃣ 创建订单"]
    E --> F{"订单<br/>创建?"}
    F -->|否| Err3["❌ 系统错误"]
    Err3 --> End

    F -->|是| G["4️⃣ 发起支付"]
    G --> H{"支付<br/>成功?"}
    H -->|否| Err4["❌ 支付失败"]
    Err4 --> End

    H -->|是| I["5️⃣ 订单确认"]
    I --> J["6️⃣ 发送通知"]
    J --> K["✅ 结账完成"]
    K --> End
```

### 流程分析

```
┌─ Start ─┐
│         │
├─ Step 1 ──┐
│ 验证购物车  │
├─ Decision 1: 有效?
│           ├─ 否 → Err1 → End
│           └─ 是 ↓
├─ Step 2
│ 计算价格
├─ Decision 2: 正确?
│           ├─ 否 → Err2 → End
│           └─ 是 ↓
├─ Step 3, 4, 5, 6
│ 继续主流程
└─ End ─┘
```

**关键特点**：
1. **主流程竖向** — 核心步骤从上到下
2. **错误路径右侧** — 错误都汇聚到 End
3. **决策分支清晰** — 每个决策有 "是/否" 标签
4. **步骤编号** — 便于理解执行顺序

## 💡 设计最佳实践

### ✅ 何时使用流程图

1. **业务流程** — 订单处理、用户注册、支付流程
2. **决策树** — if/else 分支、条件判断
3. **错误处理** — 多个错误路径和恢复逻辑
4. **算法** — 展示算法的执行步骤

### ✅ 设计建议

| 建议 | 原因 | 例子 |
|------|------|------|
| **使用 TD 方向** | 竖向更清晰 | `flowchart TD` |
| **限制分支深度** | 超过 3 层很复杂 | 避免深层嵌套 |
| **错误路径统一** | 便于理解 | 所有错误汇聚到结束 |
| **步骤有意义的名称** | 自文档化 | "验证购物车"而非"Check" |
| **使用编号/图标** | 增强可读性 | 1️⃣ 步骤 A, ❌ 错误 |
| **颜色编码** | 视觉区分 | 开始绿、成功蓝、错误红 |

### ❌ 常见错误

| 错误 | 改进方案 |
|------|--------|
| 使用 LR 方向 | 改用 TD（竖向） |
| 分支过多 | 分解成多个图表 |
| 节点名称过长 | 用简短的文本 + 换行 |
| 没有错误路径 | 添加异常处理分支 |
| 颜色过多 | 保持 4-5 种统一颜色 |

## 🎨 颜色编码规范

| 类型 | 颜色 | 十六进制 | 用途 |
|------|------|---------|------|
| 开始 | 🟢 绿 | #90EE90 | 流程开始 |
| 成功 | 🔵 蓝 | #87CEEB | 正常完成 |
| 警告 | 🟡 黄 | #FFD700 | 用户输入错误 |
| 错误 | 🔴 红 | #FF6347 | 系统错误 |
| 其他错误 | 🟠 橙 | #FFA500 | 业务逻辑错误 |
| 结束 | 🔴 粉 | #FFB6C6 | 流程结束 |

### 使用方式

```mermaid
style Start fill:#90EE90,stroke:#333,stroke-width:2px
style Success fill:#87CEEB,stroke:#333,stroke-width:2px
style Error fill:#FF6347,stroke:#333,stroke-width:1.5px
```

## 🎓 进阶技巧

### 1. 子流程（SubGraph）

```mermaid
flowchart TD
    subgraph 支付模块
        A[验证支付]
        B[处理支付]
    end
```

### 2. 循环（Loop）

```mermaid
flowchart TD
    A[开始] --> B{重试?}
    B -->|是| A
    B -->|否| C[结束]
```

### 3. 并行（Parallel）

```mermaid
flowchart LR
    A[开始] --> B[任务1]
    A --> C[任务2]
    B --> D[合并]
    C --> D
```
